# Braze REST API — capability survey

**Platform key:** `braze`
**Base URL:** `https://rest.<cluster>.braze.com` (cluster from the dashboard URL, e.g. `iad-01`, `fra-02`)
**Auth:** `Authorization: Bearer <REST API key>`, with per-endpoint permission scopes assigned to the key
**API version:** Braze's REST API is **unversioned globally** — there is no version segment or version header on the majority of endpoints. Version numbers appear only in individual path families: `/v2/subscription/status/set`, `/preference_center/v1/*`, `/transactional/v1/*`, `/scim/v2/*`, `/v1/device-messaging/*`.
**Verified against live docs:** 2026-08-24 (every row below was fetched from `www.braze.com/docs` on that date; Braze docs carry no per-page "last updated" stamp).
**Endpoint inventory source:** <https://www.braze.com/docs/api/home> (the complete endpoint index) and <https://www.braze.com/docs/api/basics> (auth, key permission scopes, rate limits).

Default rate limit is 250,000 requests/hour for most endpoints; several families carry their own tighter limit (noted per row).

## 2. Proposed NEW operations

Op keys are platform-neutral camelCase — each was chosen so it reads sensibly for Iterable, Klaviyo, Customer.io, Mailchimp and SFMC too.

### 2a. Journey / flow structure (the largest gap)

| Op key | Platform-neutral label | Braze endpoint | Doc URL | R/W | Why it matters for lifecycle |
|---|---|---|---|---|---|
| `listJourneys` | list automated journeys/flows | `GET /canvas/list` | <https://www.braze.com/docs/api/endpoints/export/canvas/get_canvases> | read | Journeys are a distinct primitive from broadcast campaigns. Orbit currently folds Canvases into `listCampaigns`, so a caller cannot ask "show me my automated flows" without also getting one-off blasts. Every listed ESP separates these (Klaviyo flows, Iterable workflows, Customer.io campaigns, SFMC interactions). |
| `getJourney` | read one journey's full step graph | `GET /canvas/details` | <https://www.braze.com/docs/api/endpoints/export/canvas/get_canvas_details> | read | **The single most valuable thing Orbit is not modelling.** Returns `variants` (with `first_step_ids`), `channels`, and `steps` — each step carrying `name`, `type`, `next_step_ids`, `next_paths`, `channels`, and a `messages` object keyed by message variation ID with the actual channel content (email subject, body, headers). ## 3. Explicitly UNSUPPORTED — commonly expected, genuinely not available

Every entry below was checked against the complete endpoint index at <https://www.braze.com/docs/api/home>, which enumerates the public REST surface. Absence from that index is the evidence.

| Expected capability | Status | Reason | Nearest alternative |
|---|---|---|---|
| **Auth ping / health check** | unsupported | No dedicated ping endpoint exists anywhere in the endpoint index or in <https://www.braze.com/docs/api/basics>. | A cheap scoped GET (`/templates/email/list?limit=1`). State which permission scope the probe actually proved. |
| **Read a segment's filter definition** | unsupported | `/segments/details` returns only a prose `description`/`text_description` of the filters, never machine-readable criteria. <https://www.braze.com/docs/api/endpoints/export/segments/get_segment_details> | Read the prose description and the size series (`/segments/data_series`); the definitive answer is the dashboard. |
| **Create or edit a segment** | unsupported | No POST/PUT/PATCH on `/segments` in the endpoint index. Segments are dashboard-authored. | `/users/track` to write the attributes a segment filters on. |
| **Create or edit a campaign or Canvas** | unsupported | The only campaign/Canvas writes are trigger, schedule, duplicate and translation updates — there is no create/update of campaign or Canvas *structure*. | `POST /campaigns/duplicate` / `POST /canvas/duplicate` to clone an existing one, then edit in the dashboard. |
| **Sending-domain / SPF / DKIM / DMARC authentication status** | unsupported | No sending-identity or domain-authentication endpoint exists in the index. Braze exposes SPF/DKIM/DMARC pass rates only through the in-dashboard Deliverability Center (<https://www.braze.com/docs/user_guide/analytics/dashboards/deliverability_center>); setup is documented as a dashboard + DNS task (<https://www.braze.com/docs/user_guide/message_building_by_channel/email/email_setup/authentication>). | Orbit's own DNS-side checks (`orbit_check_email_auth`, `orbit_check_bimi`) query the records directly — that is the honest substitute, and it is arguably better evidence than an ESP self-report. |
| **Webhook / event-stream subscription configuration read** | unsupported | Braze's outbound event stream is **Currents**, configured in-dashboard and delivered to a data lake or partner; there is no REST endpoint to list or manage Currents connectors.
