# Iterable — public API capability survey

**Platform key:** `iterable`
**API version verified:** Iterable API **1.8** (`info.version` in the live spec)
**Verified on:** 2026-08-24
**Base URL:** `https://api.iterable.com` (EU: `https://api.eu.iterable.com`)
**Auth:** `Api-Key: <key>` request header (`securityDefinitions.api_key`: `{ in: header, name: Api-Key, type: apiKey }`)
**Templating:** Handlebars

## Method and primary source

Every endpoint claim below was verified against Iterable's **live, unauthenticated
OpenAPI (Swagger 2.0) document**, fetched 2026-08-24:

- Machine-readable spec: <https://api.iterable.com/api-docs> (HTTP 200, no credential required, 284 KB, 129 paths)
- Human reference (Swagger UI over the same spec): <https://api.iterable.com/api/docs>
- EU twin: <https://api.eu.iterable.com/api-docs> / <https://api.eu.iterable.com/api/docs>

Swagger UI anchors take the form `https://api.iterable.com/api/docs#!/<tag>/<operationId>`.
The spec's tag set is: `campaigns, catalogs, channels, commerce, email, events,
experiments, export, lists, messageTypes, metadata, push, snippets, subscriptions,
templates, users, webhooks, webPush, workflows, In-app, In-app-web, SMS, WhatsApp,
Embedded Messaging, Verify`.

**Caveat on secondary sources.** `support.iterable.com` returns HTTP 403 to
non-browser clients, so the Zendesk articles below could not be fetched
byte-for-byte in this session; they were located and their claims read through
search-index snippets. Every one is marked accordingly. **No capability claim in
the tables rests on a support article** — each rests on the OpenAPI document,
which is the platform's own machine-readable contract. Support URLs are
supplementary context only.

## 3. Explicitly UNSUPPORTED via Iterable's public API

Each of these is a capability a lifecycle operator would reasonably expect.
Verified absent by exhaustive scan of all 129 paths in
<https://api.iterable.com/api-docs> on 2026-08-24.

| Expected capability | Status | Reason (evidence) | Nearest real alternative |
|---|---|---|---|
| **Sending-identity / domain authentication status** (DKIM, SPF, DMARC, BIMI, dedicated IP / IP-pool state) | **unsupported** | No endpoint exists. A case-insensitive scan of the full spec text returns **0 occurrences** of `dkim`, `spf`, `dmarc`, `bimi`, `ippool`/`ip pool`, `sending domain`, `sender identity`, or `deliverability`. Sending domains are configured in the Iterable UI only. | Orbit's own DNS-side checks — `orbit_check_email_auth`, `orbit_check_bimi`, `orbit_check_deliverability` — which read public DNS and need no ESP credential. Template-level `fromEmail`/`replyToEmail` are readable via `getTemplate`. |
| **Journey structure — the step/tile graph** (branches, delays, splits, exits) | **partial → effectively unsupported** | `GET /api/journeys` returns journey *metadata* only. `JourneyDetails` exposes `startTileId` but there is **no** `GET /api/journeys/{id}` and no tile/step resource anywhere in the spec (`/api/journeys` and `/api/workflows/triggerWorkflow` are the only two journey-tagged paths). | Reconstruct the message layer, not the logic: `listJourneys` for entry triggers and caps, then `GET /api/campaigns` filtered on `CampaignDetails.workflowId` to enumerate the messages each journey sends. Structural QA (the Braze `orbit_read_braze_canvas` equivalent) is not achievable for Iterable. |
| **Journey / flow performance metrics** | **unsupported as a first-class read** | `GET /api/campaigns/metrics` is campaign-scoped. There is no journey-level metrics endpoint. | Join: `listJourneys` → campaigns where `workflowId` matches → `GET /api/campaigns/metrics` for those ids, aggregated client-side. The `journeyExit` export data type gives exit counts. |
| **Custom-event / event-schema catalogue** | **unsupported** | `GET /api/users/getFields` returns **user profile** fields only. There is no endpoint listing event names or event property schemas — no path in the spec returns an event definition. | Sample the shape from data: `GET /api/export/data.json?dataTypeName=customEvent` over a window, or `GET /api/export/userEvents` for one user. `JourneyDetails.triggerEventNames` reveals the events that actually drive journeys — a useful partial census. |
| **Preference-centre configuration / hosted-page state** | **unsupported** | No endpoint returns the hosted preference-centre's layout, copy, or published state. `/api/subscriptions/*` mutates a user's subscriptions; it does not describe the page. | Reconstruct the *model* behind the centre from `GET /api/channels` + `GET /api/messageTypes` (`subscriptionPolicy`, `frequencyCap`) and per-user state from `getContact`. That is enough for `orbit_audit_preference_centre` to reason about coverage, but not to see the rendered page. |
| **Aggregate deliverability / reputation metrics** (inbox placement, per-ISP breakdown, domain reputation, spam-trap signal) | **unsupported** | No endpoint. The campaign metrics CSV carries send/open/click/bounce/complaint counts only. | Event-level reconstruction via `exportEngagementEvents` (`emailBounce`, `emailComplaint`, `emailSendSkip`) grouped by recipient domain, plus Orbit's `orbit_parse_postmaster_signal` for Google Postmaster data. |
| **Template version history / revisions** | **unsupported** | No versioning resource in the spec. `ApiEmailTemplateModel` exposes `creatorUserId` and `metadata` but no revision list, and there is no rollback path. | Keep the canonical HTML in the user's template brain and treat Iterable as the derived copy — the same posture Orbit already records for Mailchimp's `getTemplate`. |
| **Template folders / labels listing** | **unsupported** | `CampaignDetails` returns `labelIds` and `labels`, but there is **no** `/api/labels` (or folder) endpoint to enumerate or resolve them — scan returns zero label-tagged paths. | Derive the label vocabulary by paging `GET /api/campaigns` and collecting distinct `labels` values. |
| **Named segment definitions (the query behind a dynamic list)** | **unsupported** | `ListDetails` for a `Dynamic` list returns `id/name/description/createdAt/listType` — the segmentation criteria are not exposed. | `getSegmentSize` for magnitude and `listSegmentMembers` for membership (both 5 req/min); the rule logic itself must be read in the Iterable UI. |
| **Per-campaign link/click-map detail (click-by-URL)** | **unsupported as an aggregate** | No click-map endpoint; `GET /api/campaigns/metrics` returns aggregate click counts only. | `exportEngagementEvents` with `dataTypeName=emailClick` returns individual click events including the URL, aggregated client-side. |

## 4. Cross-cutting notes for an implementer

- **Rate limits are per-endpoint and published in the spec description text**, not in a
  single table. The severe ones an adapter must respect: `campaigns/metrics` **10/min per
  project**; `lists/getUsers` and `lists/{id}/size` **5/min per project**; `export/data.json`
  **4/min per project**; `export/start` **1/s per organization, 4 concurrent**;
  `users/getFields`, `users/getSentMessages`, `users/forgotten` **3/s per project**;
  `templates/email/preview` **10/s per project**; `templates/email/proof` **20/s per API
  key**. Most other reads are 100/s per project. Rate-limit breach returns **429**
  (<https://support.iterable.com/hc/en-us/articles/39629320560148-API-Response-Codes>,
  *search-snippet verified only*).
- **Two responses are not JSON.** `GET /api/campaigns/metrics` and `GET /api/lists/getUsers`
  both declare response schema `string` (`text/plain`); `GET /api/experiments/metrics`
  declares `text/csv` but wraps it as `{headers, rows}`. Any adapter must parse, not
  `JSON.parse`.
- **Pagination deprecation is a live migration risk.** Both `/api/templates` and
  `/api/campaigns` warn that the unpaginated variant *"is deprecated and may be removed in
  the future"*. Orbit's current Iterable adapter should be checked for reliance on it.
- **EU residency.** Every path above exists identically on `https://api.eu.iterable.com`
  (verified: `https://api.eu.iterable.com/api-docs` returns HTTP 200). `PLATFORM_META.iterable.base_url`
  already records both — correct as written.
- **Credential hygiene.** As of 2025-11-10, keys passed in the query string or request body
  are subject to stricter rate limiting than the `Api-Key` header
  (<https://support.iterable.com/hc/en-us/articles/41044692130196-Getting-Started-with-Iterable-s-API>,
  *search-snippet verified only*). Orbit already uses the header — keep it that way.
