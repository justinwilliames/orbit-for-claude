# Mailchimp — public API capability survey

**Platform key:** `mailchimp`
**API version verified:** Mailchimp Marketing API **3.0.91** (`info.version` in the live spec)
**Verified on:** 2026-08-24
**Base URL:** `https://<dc>.api.mailchimp.com/3.0` (`host: server.api.mailchimp.com`, `basePath: /3.0`; `<dc>` is the suffix on the API key, e.g. `…-us6` → `us6`)
**Auth:** HTTP Basic (`username` = any string, `password` = API key), or OAuth 2 for third-party access
**Templating:** Mailchimp merge tags / Mailchimp Template Language

## Method and primary source

Every endpoint, parameter and response-field claim below was verified against
Mailchimp's **live, unauthenticated OpenAPI (Swagger 2.0) document**, fetched
2026-08-24:

- Machine-readable spec: <https://api.mailchimp.com/schema/3.0/Swagger.json?expand> (HTTP 200, no credential required, 10.8 MB, **181 paths / 298 operations**)
- The spec's own permalink: `https://github.com/mailchimp/mailchimp-client-lib-codegen/blob/main/spec/marketing.json` (`info.x-permalink`)
- Human reference index: <https://mailchimp.com/developer/marketing/api/>
- Limits/auth guide: <https://mailchimp.com/developer/marketing/docs/fundamentals/>

**Caveat on secondary sources.** The `mailchimp.com/developer` reference pages are
client-rendered; a machine fetch returns the page shell without the response
schemas. Every schema statement below therefore comes from the OpenAPI document,
which is the platform's own machine-readable contract. The per-resource doc URLs
cited in the tables were each HTTP-200 checked on 2026-08-24; they are the
human-facing anchor for the same operations, and the doc slug is taken from the
spec's `x-doc-structure.resources` keys so it cannot drift from the endpoint.

**Platform limits (verified, <https://mailchimp.com/developer/marketing/docs/fundamentals/>):**
"The Marketing API has a limit of **10 simultaneous connections**. You'll receive
a 429 error if you reach the limit." and "a **120-second timeout** on API calls."
No per-minute or per-day quota is documented. Collection endpoints cap at
`count=1000` with `offset` pagination, and support `fields` / `exclude_fields`
projection — both matter for keeping Orbit's payloads small.

| **Read a Customer Journey / Automation-flow structure** | **unsupported** | The resource "Automation flows (Previously Customer Journeys)" contains exactly **one** operation in spec 3.0.91 — `POST /customer-journeys/journeys/{journey_id}/steps/{step_id}/actions/trigger`, whose description is *"A step trigger in an Automation flow. To use it, create a starting point or step from the Automation flow builder in the app using the Customer Journey API condition."* There is **no GET** for journeys, steps, or journey membership; the `journey_id`/`step_id` are handed to you by the app UI. Doc: <https://mailchimp.com/developer/marketing/api/customer-journeys-journeys-steps-actions/> | `listJourneys` over **Classic Automations** (legacy product, may be empty on modern accounts), plus manual documentation of the journey in the user's brain repo. Journey *performance* is partially reachable: the report object's own `type` field is documented as *"regular, plain-text, ab_split, rss, **automation**, variate, or auto"*, so automation sends do appear in `GET /reports` — but `automation` is **not** one of the values the `GET /reports?type=` filter accepts (`regular`/`plaintext`/`absplit`/`rss`/`variate`), so they must be filtered client-side. |
| **Read a template's stored HTML** | **unsupported** (metadata only) | `GET /templates/{template_id}` has no `html` field in its response schema. Doc: <https://mailchimp.com/developer/marketing/api/templates/> | `GET /templates/{template_id}/default-content` (editable section map), `GET /campaigns/{campaign_id}/content` (full HTML of a campaign built from it), or the `share_url`/`thumbnail` preview. | **Server-side render / preview a template with data** | **unsupported** | No render, preview or proof endpoint exists for a template in the 181-path spec (contrast Klaviyo's `POST /api/templates/{id}/render`). | Create a draft campaign, `PUT /campaigns/{id}/content` with `template_id`, then `POST /campaigns/{id}/actions/test`; or use Orbit's local `orbit_render_email_preview` + `orbit_qa_email`. |
| **Reusable content blocks / snippets** | **unsupported** | No content-block, snippet or partial resource exists in the spec. | `GET /templates/{template_id}/default-content` exposes the template's editable `sections` keys, which is the closest thing to a named block, but returns edit regions rather than a shared library. |
| **Account-level suppression / global bounce list** | **unsupported** | There is no `/suppressions` (or equivalent) path. Suppression is modelled as a per-audience member `status` (`unsubscribed`, `cleaned`) plus per-list `abuse-reports`. | `listSuppressions` (partial) — iterate audiences with `?status=cleaned` / `?status=unsubscribed`. Report per-audience, never as an account suppression list. |
| **Custom-event schema / event catalogue** | **unsupported** | Events exist only as a per-member write (`POST /lists/{list_id}/members/{subscriber_hash}/events`) and per-member read (`GET …/events`). No endpoint lists the event names defined on an account or their properties. | `listCustomFields` (merge fields) covers the custom-*attribute* schema. For events, derive the vocabulary from the user's own tracking plan. |
| **Inbound replies / Inbox** | **unsupported** (deprecated) | `GET /conversations` description, verbatim: *"Conversations has been deprecated in favor of Inbox and these endpoints don't include Inbox data. Historic conversations only; do not build a reply-monitoring feature on it. |
| **Transactional / one-off send to an arbitrary address** | **unsupported in this API** | The Marketing API has no transactional send. Mailchimp Transactional (Mandrill) is a **separate product with a separate API and its own key**, not covered by any path in spec 3.0.91. | `sendTest` (campaign-scoped, to test addresses). A real transactional need is a separate integration, not a Mailchimp Marketing capability. |
| **Documented request-rate quota / rate-limit headers** | **unsupported** | The fundamentals guide documents only *"a limit of 10 simultaneous connections"* and a *"120-second timeout"*; no per-minute quota and no rate-limit response headers are documented. <https://mailchimp.com/developer/marketing/docs/fundamentals/> | Bound concurrency at ≤10, treat 429 as backpressure, use `fields=`/`count=1000` projection and `runBatch` for read-heavy audits. |
| **Omni-channel contact model with consent (`/audiences` BETA)** | **do not build on** | The `Audiences (BETA)` and `Contacts` resources carry this in their own description: *"available for evaluation or testing purposes only, may contain bugs or errors… Intuit may modify or discontinue this feature at any time without notice."* Doc: <https://mailchimp.com/developer/marketing/api/audiences/> | Use `/lists` + `/lists/{id}/members`, which is the stable contract. Revisit if the BETA notice is lifted. |

## 4. Write-safety register (for the "do not automate" rule)

Mailchimp's public API exposes several irreversible or high-blast-radius writes.
None of them should ever be reachable from an unattended Orbit path:

| Operation | Endpoint | Why it is dangerous |
|---|---|---|
| Send a campaign | `POST /campaigns/{campaign_id}/actions/send` | Irreversible mass send. |
| Schedule / resend | `POST /campaigns/{campaign_id}/actions/schedule`, `…/actions/create-resend` | Same, delayed. |
| Bulk subscribe/unsubscribe | `POST /lists/{list_id}` (Batch subscribe or unsubscribe) | Mass consent-state mutation on an audience. |
| Permanently delete a contact | `POST /lists/{list_id}/members/{subscriber_hash}/actions/delete-permanent` | **Irreversible**; the address cannot be re-added and history is destroyed. |
| Forget a contact | `POST /audiences/{audience_id}/contacts/{contact_id}/actions/forget` | Irreversible GDPR erasure (and on a BETA resource). |
| Any `DELETE` | lists, segments, templates, campaigns, merge fields, webhooks, files | Destructive; merge-field deletion also drops the stored values. |
| Batch with mutating operations | `POST /batches` | Amplifies every row above; failures surface only in `response_body_url`. |
| Account export | `POST /account-exports` | Materialises subscriber PII into a downloadable archive. |
| Overwrite a template | `PATCH /templates/{template_id}` | `html` is **required**, and the API cannot return the current HTML — a partial update silently replaces the live body. |

`sendTest` (`POST /campaigns/{campaign_id}/actions/test`) is the one write Orbit
already performs; it is bounded to explicit test addresses and is safe to keep.
