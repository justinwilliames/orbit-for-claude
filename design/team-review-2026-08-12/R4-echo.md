## What I found

### The exact overclaim that just got fixed in four files is still live in ten more — including the site's own default meta and the download page's own `<title>`

`988a212`'s commit message is explicit about the bug shape it was closing: *"Four surfaces
written to make the account wall honest said the free account is 'an email address,
nothing else'. The form collects six fields."* It grepped for and fixed that exact
string. But the same claim also ships under a shorter phrasing — "one email to download"
— which makes an identical promise (single field, no password, no security question) in
different words, and that phrasing was never part of the search:

```
$ grep -rln "one email" app lib components --include="*.tsx" --include="*.ts"
app/layout.tsx
app/llms.txt/route.ts
app/about/justin/page.tsx
app/glossary/page.tsx
app/certifications/[certId]/page.tsx
app/downloads/page.tsx
lib/chat/knowledge-base.ts
components/orbit-cta.tsx
components/McpCtaBanner.tsx
(+3 unrelated guide-content hits using "one email" to mean "a single email send")
```

The two highest-reach instances:

**`app/layout.tsx`** — this is the sitewide default. Its own comment says so: *"Sitewide
default OG card generated by /api/og. Every page inherits this unless it overrides
openGraph.images."* Three separate fields all carry the claim:

```
app/layout.tsx:61   description: "...Free, no licence key, one email to download."
app/layout.tsx:85   openGraph.description: (same string)
app/layout.tsx:111  twitter.description: (same string)
```

Any page on the site that doesn't set its own `metadata` export — and any bare
`yourorbit.team` link shared with no path — unfurls in Slack, iMessage, or a Google
search snippet with this text. It's the single most-seen piece of copy on the whole
domain, by construction.

**`app/downloads/page.tsx`** — the page `FINAL-SHIPPING-DECISION.md` calls "the canonical
free install surface," and the exact page whose own doc-comment says *"the copy on this
page has to say so before the click, not after it — a button that promises a file and
delivers a form is the worst version of this page."* That discipline was applied to the
page body (line 65: "an email address, so I can reach you about the build you're on" —
accurate, not overclaiming). It was never applied to the page's own `<title>` and meta
tags four lines above it:

```
app/downloads/page.tsx:27   title: "Download Orbit — free, one email"
app/downloads/page.tsx:29   description: "...Free, no licence key, one email to
                              download. Double-click the .mcpb and you're running."
app/downloads/page.tsx:32   openGraph.title: "Download Orbit — free, one email"
app/downloads/page.tsx:33   openGraph.description: "...Free, no licence key, one
                              email to download."
```

The `<title>` tag is what shows in the browser tab and the Google search result headline
— frequently the only thing a stranger reads before deciding whether to click through at
all. Someone who shares `yourorbit.team/downloads` in a Slack channel gets an unfurl card
that says "free, one email," landing exactly on the download page whose own body text
this cycle's fix didn't touch, sitting above the real account form: email, first name, an
8-character password with confirmation, a security question and answer
(`app/api/account/create/route.ts:119-130`, unchanged this cycle, re-confirmed by
direct read).

Two more surfaces worth naming for reach: `components/McpCtaBanner.tsx` renders the claim
("No licence key, one email to download" / "no licence key, one email to download") in
both its `sidebar` and default variants — this is the CTA block dropped into guide pages,
so it's the pitch a reader sees after finishing any of the 90 practitioner guides, i.e.
exactly the moment someone who's been sold on the value is about to click. And
`lib/chat/knowledge-base.ts:65` puts "one email to download" into the site's own chat
search index, so the in-site AI assistant repeats the same overclaim when asked how to
get Orbit — the friend-repeatable test failing inside the product's own help surface, not
just its marketing copy.

**Why this matters for my lens specifically:** the fix that just landed proved the team
already agrees this exact claim is a problem worth a dedicated commit — it named the gap
precisely ("an email address, nothing else" vs. six real fields) and closed it everywhere
that precise string appeared. The same promise survives, word-different, on the surfaces
with the most reach: the sitewide default unfurl, the download page's own headline, and
the CTA shown at the end of every guide. A friend who reads the tab title or the Slack
unfurl repeats "just one email" to the next person, who hits a password-and-security-
question form — the identical bait-and-switch the prior fix was written to prevent, one
grep pattern short of catching it everywhere.

No test guards any of this: `grep -rln "one email\|nothing else\|an email address"
tests/` returns only `tests/tripwires/text-contrast.test.mjs`, which is about colour, not
copy. The 988a212 fix added no assertion that the claim-vs-form gap can't reopen under a
different phrasing, which is exactly how it reopened.

**Fix:** same treatment as `988a212`, applied to the remaining phrasing. Suggested
replacement pattern, matching what already shipped in the four fixed files: "free, no
licence key" (drop the field-count claim from title-length copy entirely — titles don't
need to promise a field count) or, where space allows, "one email, and a password" /
"free account (a few fields, no card)." Specifically:
- `app/layout.tsx` — all three sitewide metadata strings (title stays fine; drop "one
  email to download" from the description/OG/twitter description, replace with "no
  licence key, free to install").
- `app/downloads/page.tsx` — `title`, `description`, `openGraph.title`,
  `openGraph.description` (four fields, all four lines shown above).
- `components/McpCtaBanner.tsx` — both variants' copy strings.
- `lib/chat/knowledge-base.ts:65` — the excerpt fed to the in-site chat assistant.
- `app/about/justin/page.tsx`, `app/glossary/page.tsx`,
  `app/certifications/[certId]/page.tsx` — same phrase, lower-reach but same fix.
- Add the missed phrasing to whatever check now exists (or add one) so "one email" and
  "an email address, nothing else" are both tripwired the same way `988a212` tripwired
  the inverting-filter bug it also fixed — the pattern that bug and this one share is a
  fix scoped to the exact string first reported, not the class of claim.

Evidence tag: instrumented. `grep -rln "one email" app lib components --include="*.tsx"
--include="*.ts"` output quoted above; direct `Read` of `app/layout.tsx`,
`app/downloads/page.tsx`, `components/McpCtaBanner.tsx`, and
`app/api/account/create/route.ts` (field list unchanged from R3, re-confirmed this cycle);
`git show 988a212 --stat` confirms none of the ten files above were touched by the fix
commit; `grep -rln` across `tests/` confirms no regression test covers this phrasing.
